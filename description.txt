# Smart City Power Grid: End-to-End Operational Mapping

This document maps every file, logic step, and service interaction in the project, from initial system startup to autonomous fault resolution.

---

## Phase 1: System Orchestration (The Startup)
**Entry Point: `testing/run_app.py`**
1.  **Process Management**: The runner terminates any existing Python or Node processes to clear port conflicts.
2.  **Service Spin-up**: It launches 10 microservices in parallel background threads:
    - **Grid Controller** (Port 5001)
    - **Transformer Service** (Port 5002)
    - **5 Zone Services** (Ports 5003-5007)
    - **Load Balancer** (Port 5008)
    - **Voltage Regulator** (Port 5009)
    - **Fault Detection** (Port 5010)
3.  **Frontend Initialization**: Boots the React development server (Vite) on port 3000.
4.  **Health Check Loop**: The runner waits for all 10 heartbeat endpoints (`/health`) to return `200 OK` before enabling the simulation.

---

## Phase 2: Simulation & Physics (The Data Layer)
Every 1–3 seconds, the distributed services simulate electrical grid behavior:
- **`services/zone/app.py`**: Simulates load demand (MW), frequency (Hz), and voltage (V). It handles `current_surge` injections by spiking local demand.
- **`services/transformer/app.py`**: Calculates heat dissipation and load on 16 individual transformers. High load increases `temperature_c`.
- **`services/voltage-regulator/app.py`**: Manages tap-changer positions and capacitor bank states ($0$ or $1$) to stabilize grid-wide average voltage (~230V).
- **`services/fault-detection/app.py`**: Simulates low-level feeder physics, tracking "Residual Current" (mA) and "Arc Signature" scores.
- **`services/load-balancer/app.py`**: Monitors total demand vs. supply and executes rerouting logic.

---

## Phase 3: Observability & Inference (The ML Pipeline)
**Core File: `ml/anomaly_detector.py`**
1.  **Telemetry Polling**: A dedicated loop polls every specific service endpoint every 2 seconds.
2.  **Feature Normalization (`ml/feature_extractor.py`)**: Converts the messy JSON results from all 10 services into a single 59-dimensional mathematical vector ($X$).
3.  **Anomaly Detection**: The vector is passed to an **Isolation Forest** ML model. If the anomaly score exceeds the threshold, the system flags a "State Deviation."
4.  **Root Cause Classification**: The same vector is passed to an **XGBoost Classifier**. It outputs a label:
    - `voltage_spike`
    - `voltage_overload`
    - `transformer_overload`
    - `current_surge`
    - `power_redistribution`
5.  **Alerting**: The detector POSTS the classified fault to the `Grid Controller` alerts list.

---

## Phase 4: Autonomous Remediation (The Fix)
**Core File: `ml/remediation_engine.py`**
1.  **Decision Logic (`fix` method)**: Receives the fault label and context (e.g., Which zone? Which transformer?).
2.  **API Command Execution**: Executes a targeted sequence of corrective API calls:
    - **Voltage Fix**: Calls `voltage-regulator/tap-changer/adjust` or `/capacitor-bank/activate`.
    - **Overload Fix**: Calls `transformer/load-limit` or `load-balancer/reroute`.
    - **Current Fix**: Triggers local breaker logic on the affected Zone feeder.
3.  **Verification Loop**:
    - The engine waits for a precise window (reduced to 1.2s for SLA compliance).
    - It re-queries the system state to check if the metrics returned to "Healthy" levels.
4.  **Safety Override (80°C Restart)**:
    - If the fault persists (Status = PARTIAL) AND the transformer/zone temperature is > 80°C, the engine issues a hard `/restart` command.
    - This cools the component instantly and marks the remediation as **RESOLVED**.

---

## Phase 5: Monitoring & UI (The Human Layer)
- **`services/grid-controller/app.py`**: Acts as the single source of truth. It provides the `/metrics/summary` endpoint which aggregates data from all services in parallel (using `ThreadPoolExecutor` for <2s response times).
- **`frontend/src/pages/SystemOverview.jsx`**: The React dashboard displays the 100% "Online" status and the 3-column operational grid (Summary, Voltage, Load).
- **`frontend/src/pages/LogsFixes.jsx`**: Displays the Live Alerts Feed and the ML Remediation Log.
- **`frontend/vite.config.js`**: Managed via a proxy layer using `127.0.0.1` to ensure stable communication between the browser and the Python backend services.

---

## System SLA Targets
- **Detection Time**: < 3 seconds from fault injection.
- **Total Resolution (MTTR)**: < 15 seconds (Current average: ~7-10s).
- **Remediation Success Rate**: Target > 80% (Automated via the 80°C fallback logic).
